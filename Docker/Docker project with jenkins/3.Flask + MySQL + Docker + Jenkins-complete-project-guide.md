# Flask + MySQL + Docker + Jenkins — Complete Project, Start to Finish

This is the full build log of a real project: a Flask web app backed by MySQL, containerized with Docker, networked properly, made persistent with a volume, wired into an automated Jenkins CI/CD pipeline with tests, and finally upgraded to a zero-downtime blue-green deployment. Every command and file below was actually built and run, in order.

### 1.3 The Flask application (`flask-app/app.py`)

A note-taking app: a form to submit a message, stored in MySQL, listed back on the page.

```python
from flask import Flask, request
import mysql.connector

app = Flask(__name__)

db_config = {
    "host": "db-container",
    "user": "flaskuser",
    "password": "flaskpass",
    "database": "mydb"
}

def get_connection():
    return mysql.connector.connect(**db_config)

def ensure_table():
    conn = get_connection()
    cursor = conn.cursor()
    cursor.execute("""
        CREATE TABLE IF NOT EXISTS notes (
            id INT AUTO_INCREMENT PRIMARY KEY,
            message VARCHAR(255)
        )
    """)
    conn.commit()
    cursor.close()
    conn.close()

@app.route("/", methods=["GET", "POST"])
def home():
    if request.method == "POST":
        message = request.form.get("message")
        if message:
            conn = get_connection()
            cursor = conn.cursor()
            cursor.execute("INSERT INTO notes (message) VALUES (%s)", (message,))
            conn.commit()
            cursor.close()
            conn.close()

    conn = get_connection()
    cursor = conn.cursor()
    cursor.execute("SELECT id, message FROM notes ORDER BY id DESC")
    rows = cursor.fetchall()
    cursor.close()
    conn.close()

    rows_html = "".join(f"<li>#{r[0]}: {r[1]}</li>" for r in rows)

    return f"""
    <h2>Add a note</h2>
    <form method="POST">
        <input type="text" name="message" placeholder="Type something...">
        <button type="submit">Save</button>
    </form>
    <h3>Saved notes:</h3>
    <ul>{rows_html}</ul>
    """

if __name__ == "__main__":
    ensure_table()
    app.run(host="0.0.0.0", port=5000)
```

`"host": "db-container"` uses the **container name**, not an IP — this only works because both containers share the custom network from step 1.2.

### 1.4 Automated tests (`flask-app/test_app.py`)

Uses Flask's test client with the database connection **mocked**, so tests run fast without needing a live MySQL instance.

```python
import unittest
from unittest.mock import patch, MagicMock
import app as flask_app


class FlaskAppTestCase(unittest.TestCase):

    def setUp(self):
        self.client = flask_app.app.test_client()
        self.client.testing = True

    @patch("app.get_connection")
    def test_home_page_loads(self, mock_get_connection):
        mock_conn = MagicMock()
        mock_cursor = MagicMock()
        mock_cursor.fetchall.return_value = []
        mock_conn.cursor.return_value = mock_cursor
        mock_get_connection.return_value = mock_conn

        response = self.client.get("/")
        self.assertEqual(response.status_code, 200)
        self.assertIn(b"Add a note", response.data)

    @patch("app.get_connection")
    def test_post_note_inserts_and_redisplays(self, mock_get_connection):
        mock_conn = MagicMock()
        mock_cursor = MagicMock()
        mock_cursor.fetchall.return_value = [(1, "Test note from pytest")]
        mock_conn.cursor.return_value = mock_cursor
        mock_get_connection.return_value = mock_conn

        response = self.client.post("/", data={"message": "Test note from pytest"})
        self.assertEqual(response.status_code, 200)
        self.assertIn(b"Test note from pytest", response.data)
        mock_cursor.execute.assert_any_call(
            "INSERT INTO notes (message) VALUES (%s)", ("Test note from pytest",)
        )

    @patch("app.get_connection")
    def test_empty_message_not_inserted(self, mock_get_connection):
        mock_conn = MagicMock()
        mock_cursor = MagicMock()
        mock_cursor.fetchall.return_value = []
        mock_conn.cursor.return_value = mock_cursor
        mock_get_connection.return_value = mock_conn

        self.client.post("/", data={"message": ""})
        insert_calls = [
            c for c in mock_cursor.execute.call_args_list
            if "INSERT INTO notes" in str(c)
        ]
        self.assertEqual(len(insert_calls), 0)


if __name__ == "__main__":
    unittest.main()
```

### 1.5 The Dockerfile (`flask-app/Dockerfile`)

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY app.py .
COPY test_app.py .
RUN pip install flask mysql-connector-python pytest
EXPOSE 5000
CMD ["python3", "app.py"]
```

| Instruction | Purpose |
|---|---|
| `FROM python:3.11-slim` | Minimal base image with Python 3.11 |
| `WORKDIR /app` | Sets the working directory inside the image |
| `COPY app.py .` / `COPY test_app.py .` | Copies the app and its tests into the image |
| `RUN pip install ...` | Installs Flask, the MySQL driver, and pytest at build time |
| `EXPOSE 5000` | Documents the port (doesn't publish it — that's `-p` at run time) |
| `CMD [...]` | Default command when a container starts |

## Part 2 — Manual Docker Run (Before Automation)

### 2.1 Build and run the database

```bash
docker volume create db-data

docker run -d \
  --name db-container \
  --network myapp-network \
  -e MYSQL_ROOT_PASSWORD=rootpass \
  -e MYSQL_DATABASE=mydb \
  -e MYSQL_USER=flaskuser \
  -e MYSQL_PASSWORD=flaskpass \
  -v db-data:/var/lib/mysql \

```

No `-p` flag — MySQL only needs to be reachable by Flask over the internal network, not from the host or outside world.

```bash
cd flask-app

  --name flask-container \
  --network myapp-network \
  -p 5000:5000 \

```

## Part 5 — Basic CI/CD Pipeline (Build, Test, Push, Deploy)

This was the first working automated version — checkout, build, test, push, deploy, verify, all in sequence, with a failure at any stage automatically skipping everything after it.

```groovy
pipeline {
    agent any

    environment {
        IMAGE_REPO = "naim8855/flask-app"
        NETWORK_NAME = "myapp-network"
        VOLUME_NAME = "db-data"
        IMAGE_TAG = "v${BUILD_NUMBER}"
    }

    stages {

        stage('Checkout Code') {
            steps {
                checkout scm
            }
        }

        stage('Build Image') {
            steps {
                dir('flask-app') {
                    sh '''
                        docker build -t $IMAGE_REPO:$IMAGE_TAG -t $IMAGE_REPO:latest .
                    '''
                }
            }
        }

        stage('Run Tests') {
            steps {
                sh '''
                    docker run --rm $IMAGE_REPO:$IMAGE_TAG python3 -m pytest test_app.py -v
                '''
            }
        }

        stage('Login to Docker Hub') {
            steps {
                withCredentials([usernamePassword(
                    credentialsId: 'dockerhub-creds',
                    usernameVariable: 'DOCKER_USER',
                    passwordVariable: 'DOCKER_PASS'
                )]) {
                    sh 'echo $DOCKER_PASS | docker login -u $DOCKER_USER --password-stdin'
                }
            }
        }

        stage('Push Image') {
            steps {
                sh '''
                    docker push $IMAGE_REPO:$IMAGE_TAG
                    docker push $IMAGE_REPO:latest
                '''
            }
        }

        stage('Ensure Network Exists') {
            steps {
                sh '''
                    docker network inspect $NETWORK_NAME >/dev/null 2>&1 || \
                    docker network create $NETWORK_NAME
                '''
            }
        }

        stage('Ensure Volume Exists') {
            steps {
                sh '''
                    docker volume inspect $VOLUME_NAME >/dev/null 2>&1 || \
                    docker volume create $VOLUME_NAME
                '''
            }
        }

        stage('Start Database') {
            steps {
                sh '''
                    docker rm -f db-container || true
                    docker run -d \
                      --name db-container \
                      --network $NETWORK_NAME \
                      -e MYSQL_ROOT_PASSWORD=rootpass \
                      -e MYSQL_DATABASE=mydb \
                      -e MYSQL_USER=flaskuser \
                      -e MYSQL_PASSWORD=flaskpass \
                      -v $VOLUME_NAME:/var/lib/mysql \
                      mysql:8
                '''
            }
        }

        stage('Wait for Database') {
            steps {
                sh '''
                    for i in $(seq 1 20); do
                        docker exec db-container mysqladmin ping -uroot -prootpass --silent && break
                        echo "Waiting for MySQL..."
                        sleep 3
                    done
                '''
            }
        }

        stage('Deploy Flask App') {
            steps {
                sh '''
                    docker rm -f flask-container || true
                    docker run -d \
                      --name flask-container \
                      --network $NETWORK_NAME \
                      -p 5000:5000 \
                      $IMAGE_REPO:$IMAGE_TAG
                '''
            }
        }

        stage('Smoke Test') {
            steps {
                sh '''
                    sleep 5
                    curl -f http://localhost:5000
                '''
            }
        }
    }

    post {
        success {
            echo "Pipeline succeeded — tests passed, deployed ${IMAGE_REPO}:${IMAGE_TAG}"
        }
        failure {
            echo 'Pipeline failed — check the stage logs above.'
        }
        always {
            sh 'docker logout || true'
        }
    }
}
```

**Key concepts learned at this stage:**
- `BUILD_NUMBER` is a Jenkins built-in variable, auto-incrementing (`v1`, `v2`, `v3`...) — used for image versioning, with `latest` always pointing to the newest
- Stages run top to bottom; a failure skips everything after it automatically — no manual `if` logic needed
- Idempotent setup (`docker network inspect ... || docker network create ...`) means the pipeline can run repeatedly without erroring on things that already exist
- A failed test stage means the image is **never pushed or deployed** — proven by deliberately breaking a SQL query and watching the pipeline stop before `Push Image`

## Part 6 — Zero-Downtime Blue-Green Deployment

### 6.1 The problem

```groovy
docker rm -f flask-container   // app is now unreachable
docker run -d --name flask-container -p 5000:5000 $IMAGE_REPO:$IMAGE_TAG   // starting up
```

Between these lines, nothing answers on port 5000 — a real downtime gap on every deploy.

### 6.2 The solution — Nginx reverse proxy + alternating "blue"/"green" containers

```
Browser → Nginx (always on port 5000) → active Flask container (blue OR green)
```

Deploy the **new** color alongside the old one, health-check it, switch Nginx to point at it (a config reload, near-instant), and only then remove the old color.

### 6.3 One-time setup

```bash
mkdir -p ~/flask-db-app/nginx
nano ~/flask-db-app/nginx/nginx.conf
```

```nginx
events {}

http {
    upstream flask_backend {
        server flask-blue:5000;
    }

    server {
        listen 80;

        location / {
            proxy_pass http://flask_backend;
            proxy_set_header Host $host;
        }
    }
}
```

```bash
echo "blue" > ~/flask-db-app/active_color.txt

docker run -d \
  --name nginx-proxy \
  --network myapp-network \
  -p 5000:80 \
  -v ~/flask-db-app/nginx/nginx.conf:/etc/nginx/nginx.conf:ro \
  nginx:alpine

docker run -d --name flask-blue --network myapp-network naim8855/flask-app:latest

# Remove the old single-container setup, replaced by this new system
docker stop flask-container
docker rm flask-container
```

### 6.4 Fix file permissions so Jenkins can edit the Nginx config

The `jenkins` system user needs to read, write, and traverse into the directories holding `nginx.conf` and `active_color.txt`:

```bash
sudo chown jenkins:jenkins ~/flask-db-app/nginx/nginx.conf
sudo chmod 664 ~/flask-db-app/nginx/nginx.conf

sudo chown jenkins:jenkins ~/flask-db-app/nginx
sudo chmod 775 ~/flask-db-app/nginx

sudo chown jenkins:jenkins ~/flask-db-app/active_color.txt
sudo chmod 664 ~/flask-db-app/active_color.txt
```

`sed -i` (used to edit the config) writes a temporary file in the same folder before swapping it in — so the **directory itself** needs write permission, not just the file.

### 6.5 The final Jenkinsfile

```groovy
pipeline {
    agent any

    environment {
        IMAGE_REPO = "naim8855/flask-app"
        NETWORK_NAME = "myapp-network"
        VOLUME_NAME = "db-data"
        IMAGE_TAG = "v${BUILD_NUMBER}"
        NGINX_CONF = "/home/naim/flask-db-app/nginx/nginx.conf"
        STATE_FILE = "/home/naim/flask-db-app/active_color.txt"
    }

    stages {

        stage('Checkout Code') {
            steps {
                checkout scm
            }
        }

        stage('Build Image') {
            steps {
                dir('flask-app') {
                    sh '''
                        docker build -t $IMAGE_REPO:$IMAGE_TAG -t $IMAGE_REPO:latest .
                    '''
                }
            }
        }

        stage('Run Tests') {
            steps {
                sh '''
                    docker run --rm $IMAGE_REPO:$IMAGE_TAG python3 -m pytest test_app.py -v
                '''
            }
        }

        stage('Login to Docker Hub') {
            steps {
                withCredentials([usernamePassword(
                    credentialsId: 'dockerhub-creds',
                    usernameVariable: 'DOCKER_USER',
                    passwordVariable: 'DOCKER_PASS'
                )]) {
                    sh 'echo $DOCKER_PASS | docker login -u $DOCKER_USER --password-stdin'
                }
            }
        }

        stage('Push Image') {
            steps {
                sh '''
                    docker push $IMAGE_REPO:$IMAGE_TAG
                    docker push $IMAGE_REPO:latest
                '''
            }
        }

        stage('Ensure Network Exists') {
            steps {
                sh '''
                    docker network inspect $NETWORK_NAME >/dev/null 2>&1 || \
                    docker network create $NETWORK_NAME
                '''
            }
        }

        stage('Ensure Volume Exists') {
            steps {
                sh '''
                    docker volume inspect $VOLUME_NAME >/dev/null 2>&1 || \
                    docker volume create $VOLUME_NAME
                '''
            }
        }

        stage('Ensure Database Running') {
            steps {
                sh '''
                    if ! docker ps --format '{{.Names}}' | grep -q '^db-container$'; then
                        docker run -d \
                          --name db-container \
                          --network $NETWORK_NAME \
                          -e MYSQL_ROOT_PASSWORD=rootpass \
                          -e MYSQL_DATABASE=mydb \
                          -e MYSQL_USER=flaskuser \
                          -e MYSQL_PASSWORD=flaskpass \
                          -v $VOLUME_NAME:/var/lib/mysql \
                          mysql:8
                        for i in $(seq 1 20); do
                            docker exec db-container mysqladmin ping -uroot -prootpass --silent && break
                            sleep 3
                        done
                    else
                        echo "Database already running — skipping."
                    fi
                '''
            }
        }

        stage('Determine Active Color') {
            steps {
                script {
                    env.CURRENT_COLOR = sh(
                        script: "cat ${STATE_FILE} 2>/dev/null || echo blue",
                        returnStdout: true
                    ).trim()
                    env.NEW_COLOR = (env.CURRENT_COLOR == "blue") ? "green" : "blue"
                    echo "Current active: ${env.CURRENT_COLOR} — deploying new version as: ${env.NEW_COLOR}"
                }
            }
        }

        stage('Deploy New Color (alongside old)') {
            steps {
                sh '''
                    docker rm -f flask-$NEW_COLOR || true
                    docker run -d \
                      --name flask-$NEW_COLOR \
                      --network $NETWORK_NAME \
                      $IMAGE_REPO:$IMAGE_TAG
                '''
            }
        }

        stage('Health Check New Color') {
            steps {
                sh '''
                    for i in $(seq 1 10); do
                        if docker run --rm --network $NETWORK_NAME curlimages/curl:latest \
                          curl -sf http://flask-$NEW_COLOR:5000 > /dev/null; then
                            echo "flask-$NEW_COLOR is healthy."
                            break
                        fi
                        echo "Waiting for flask-$NEW_COLOR to become reachable... ($i/10)"
                        sleep 2
                    done
                '''
            }
        }

        stage('Switch Traffic to New Color') {
            steps {
                sh '''
                    sed -i "s/server flask-[a-z]*:5000;/server flask-$NEW_COLOR:5000;/" $NGINX_CONF
                    docker exec nginx-proxy nginx -s reload
                    echo -n "$NEW_COLOR" > $STATE_FILE
                '''
            }
        }

        stage('Remove Old Color') {
            steps {
                sh '''
                    docker rm -f flask-$CURRENT_COLOR || true
                '''
            }
        }

        stage('Final Verification') {
            steps {
                sh '''
                    for i in $(seq 1 10); do
                        if curl -sf http://localhost:5000 > /dev/null; then
                            echo "Verified — Nginx is correctly serving flask-$NEW_COLOR."
                            break
                        fi
                        echo "Waiting for Nginx to settle onto flask-$NEW_COLOR... ($i/10)"
                        sleep 2
                    done
                    curl -f http://localhost:5000
                    echo ""
                    echo "Zero-downtime deploy complete — live version is now: $NEW_COLOR"
                '''
            }
        }
    }

    post {
        success {
            echo "Pipeline succeeded — ${IMAGE_REPO}:${IMAGE_TAG} live as flask-${env.NEW_COLOR}, switched with zero downtime"
        }
        failure {
            echo 'Pipeline failed — old version was left running untouched, nothing was switched.'
        }
        always {
            sh 'docker logout || true'
        }
    }
}
```

**Important:** `NGINX_CONF` and `STATE_FILE` must match wherever these files actually live. Confirm with:
```bash
find / -name "nginx.conf" -path "*flask-db-app*" 2>/dev/null
find / -name "active_color.txt" 2>/dev/null
```

## Part 7 — Real Problems Hit and Fixed Along the Way

| Problem | Symptom | Fix |
|---|---|---|
| `jenkins` user can't run Docker | `permission denied ... docker.sock` | `sudo usermod -aG docker jenkins` + restart Jenkins |
| Wrong image name pushed vs referenced | `pull access denied` / `no such image` | Confirm exact name with `docker images`, match it everywhere |
| File permission denied on `nginx.conf` | `sed: can't read ...: Permission denied` | `sudo chown jenkins:jenkins <file>` + `chmod 664` |
| File not found at expected path | `sed: can't read ...: No such file or directory` | Project existed under both `/root/...` and `/home/naim/...` at different times — locate the real path with `find` and make the Jenkinsfile match |
| Config file was actually a directory | `sed` can't treat it as text | Docker auto-creates a missing bind-mount path as a **directory**; remove the bogus folder (`rm -rf`) and create a real file instead |
| `sed` fails even with correct file permissions | `couldn't open temporary file ...: Permission denied` | `sed -i` needs write access to the **parent directory**, not just the file — `chmod 775` on the folder |
| `502 Bad Gateway` right after switching | `Host is unreachable` in Nginx logs | Brief race condition right after a new container attaches to the network — replaced single-shot health checks with retry loops |

## Part 9 — What This Project Demonstrates, End to End

- **Docker fundamentals**: images, containers, `Dockerfile` instructions, networking, volumes, bind mounts
- **Multi-container communication**: Flask reaching MySQL purely by container name via Docker's internal DNS
- **Persistence**: a named volume surviving full container deletion and recreation
- **CI**: automated build, automated tests that gate deployment, versioned image tags
- **CD**: automated push to a registry, automated deployment
- **Production-adjacent practices**: secrets kept out of code via Jenkins credentials, idempotent pipeline stages, zero-downtime deployment via a reverse proxy and blue-green container swapping, retry-based health checks resilient to real-world timing variance
- **Real debugging**: permission chains across users/directories, Docker's bind-mount auto-create behavior, and race conditions in container networking — all genuine issues a working DevOps pipeline runs into, not contrived exercises
