# Docker Basic Commands — Quick Reference

A practical cheat sheet of the core Docker commands, grouped by purpose, with a short explanation of what each one does.

---

## 1. Images

```bash
docker pull <image>                 # download an image from a registry (e.g. Docker Hub)
docker images                       # list all images on your machine
docker build -t <name> .            # build an image from a Dockerfile in the current folder
docker build -t <name>:<tag> .      # build with a specific tag/version
docker tag <image> <new-name>       # give an existing image an additional name/tag
docker rmi <image>                  # remove an image
docker history <image>              # see the layers that make up an image
docker image prune                  # remove unused (dangling) images
docker image prune -a               # remove ALL unused images, not just dangling ones
```

---

## 2. Containers — Lifecycle

```bash
docker run <image>                              # create and start a new container
docker run -d <image>                           # run detached (in the background)
docker run -it <image> bash                      # run interactively with a shell
docker run --name <name> <image>                 # give the container a specific name
docker run -p <host_port>:<container_port> <image>   # map a port so it's reachable from the host
docker run -e KEY=value <image>                  # set an environment variable
docker run -v <volume>:<path> <image>            # attach a volume or bind mount
docker run --network <name> <image>              # attach to a specific network
```

```bash
docker ps                    # list running containers
docker ps -a                 # list ALL containers, including stopped ones
docker start <container>     # start a stopped container
docker stop <container>      # gracefully stop a running container
docker restart <container>   # stop then start again (same container, same ID)
docker rm <container>        # remove a container (must be stopped first, or use -f)
docker rm -f <container>     # force remove, even if running
```

---

## 3. Interacting With a Running Container

```bash
docker exec -it <container> bash   # open a shell inside a running container
docker exec -it <container> sh     # same, for minimal images without bash (e.g. Alpine)
docker exec <container> <command>  # run a single command inside the container
docker logs <container>            # view a container's output/logs
docker logs -f <container>         # follow the logs live (like tail -f)
docker attach <container>          # attach your terminal to a container's main process (only works if it's still running)
docker inspect <container>         # full JSON details about a container (config, network, mounts, etc.)
docker stats                       # live CPU/memory/network usage for all running containers
docker top <container>             # see the processes running inside a container
```

## 4. Dockerfile Basics (for reference)

```dockerfile
FROM <base-image>        # starting point for the image
WORKDIR /app              # sets the working directory inside the image
COPY <src> <dest>         # copy files from host into the image
RUN <command>              # execute a command at BUILD time (e.g. install packages)
ENV KEY=value              # set an environment variable
ARG KEY=default             # build-time-only variable (use --build-arg to override)
EXPOSE <port>               # documents the port used (does NOT publish it)
USER <username>             # switch to a non-root user
CMD ["executable", "arg"]   # default command, run at container START time (overridable)
ENTRYPOINT ["executable"]   # fixed command, run at container START time (hard to override)
```

## 5. Volumes

```bash
docker volume create <name>     # create a named volume
docker volume ls                # list all volumes
docker volume inspect <name>    # see details, including real host location
docker volume rm <name>         # delete a volume (must not be in use)
docker volume prune             # remove all unused volumes
```

```bash
docker run -v <volume-name>:<container-path> <image>          # named volume
docker run -v <host-path>:<container-path> <image>             # bind mount
docker run -v <source>:<container-path>:ro <image>              # mount read-only
```

## 6. Networking

```bash
docker network ls                          # list all networks
docker network create <name>               # create a custom bridge network
docker network inspect <name>               # see subnet, gateway, connected containers
docker network rm <name>                    # delete a network
docker network connect <network> <container>     # attach a running container to another network
docker network disconnect <network> <container>  # remove a running container from a network
```

---

## 7. Docker Compose

```bash
docker compose up -d           # build/start everything defined in compose.yml (detached)
docker compose down            # stop and remove containers + network (volumes kept by default)
docker compose down -v         # also remove named volumes
docker compose ps              # list services in this project
docker compose logs            # view logs from all services
docker compose logs -f <service>   # follow logs for one specific service
docker compose build           # build/rebuild images
docker compose exec <service> <command>   # run a command inside a running service
docker compose restart         # restart all services
docker compose stop / start    # stop/start without removing
docker compose config          # validate and print the resolved config
```

---

## 8. Cleanup / Maintenance

```bash
docker system df                    # see disk usage: images, containers, volumes
docker container prune              # remove all stopped containers
docker image prune                  # remove dangling (untagged) images
docker image prune -a               # remove all unused images
docker volume prune                 # remove unused volumes (careful — checks in-use status first)
docker network prune                # remove unused networks
docker system prune                 # remove stopped containers + dangling images + unused networks
docker system prune -a --volumes    # remove EVERYTHING unused, including volumes (most aggressive)
```

---

## 9. Common Combos Worth Remembering

```bash
docker ps -a | grep <name>                       # find a specific container by name
docker rm -f $(docker ps -aq)                     # remove ALL containers (stopped or running)
docker rmi $(docker images -q)                    # remove ALL images
docker exec -it <container> sh -c "command"       # run a shell command string inside a container
docker run --rm <image>                            # auto-delete the container once it exits (good for throwaway tasks)
```

---

## 10. Quick Decision Guide

| I want to... | Use |
|---|---|
| See what's running right now | `docker ps` |
| See everything, including stopped | `docker ps -a` |
| Get inside a running container | `docker exec -it <container> sh` (or `bash`) |
| See what a container printed/logged | `docker logs <container>` |
| Make a container reachable from my browser | `-p host:container` at `docker run` |
| Keep data after the container is deleted | `-v volume-name:/path` (named volume) or `-v /host/path:/path` (bind mount) |
| Let two containers talk to each other by name | Put both on the same custom network (`docker network create` + `--network`) |
| Free up disk space | `docker system df` first, then the relevant `prune` command |
| Run a full multi-container app from one file | `docker compose up -d` |
