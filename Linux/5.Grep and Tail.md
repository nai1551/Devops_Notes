# Grep and Tail — Linux Practice Guide

## 1. Introduction

`grep` and `tail` are two very useful Linux commands for working with text files and log files.

- `grep` → searches for text or patterns.
- `tail` → displays the end of a file.
- `|` (pipe) → sends the output of one command to another command.

---

# 2. GREP

## Basic Syntax

```bash
grep "pattern" filename
```

### Example

```bash
grep "ERROR" server.log
```

This displays every line containing `ERROR`.

---

## Common grep Options

### `-i` — Ignore Case

```bash
grep -i "linux" file.txt
```

Matches:

```text
Linux
linux
LINUX
LiNuX
```

---

### `-n` — Show Line Numbers

```bash
grep -n "ERROR" server.log
```

Example output:

```text
5:2026-08-27 08:20:31 ERROR Database connection failed
9:2026-08-27 08:45:33 ERROR Docker container stopped
```

---

### `-c` — Count Matching Lines

```bash
grep -c "ERROR" server.log
```

Example:

```text
4
```

This means there are 4 lines containing `ERROR`.

---

### `-v` — Invert Match

```bash
grep -v "ERROR" server.log
```

Displays lines that do **not** contain `ERROR`.

---

### `-E` — Extended Regular Expressions

Search for multiple patterns:

```bash
grep -E "ERROR|WARNING" server.log
```

This finds lines containing either:

- `ERROR`
- `WARNING`

---

### `-r` — Recursive Search

Search inside files in directories and subdirectories:

```bash
grep -r "Docker" /var/log
```

---

### `-o` — Show Only Matching Text

```bash
grep -o "ERROR" server.log
```

Instead of displaying the complete line, it displays only the matching text.

# 4. TAIL

`tail` displays the last part of a file.

## Basic Syntax

```bash
tail filename
```

By default, `tail` displays the last 10 lines.

### Example

```bash
tail server.log
```

---

## `-n` — Number of Lines

Display the last 5 lines:

```bash
tail -n 5 server.log
```

Display the last 20 lines:

```bash
tail -n 20 server.log
```

Short form:

```bash
tail -5 server.log
```

---

## `-f` — Follow a File

```bash
tail -f server.log
```

This continuously monitors the file.

When new lines are added, they appear automatically.

Stop with:

```text
Ctrl+C
```

This is especially useful for monitoring application and server logs.

---

## `tail -n +N`

Display the file starting from a specific line.

Example:

```bash
tail -n +11 server.log
```

This displays everything starting from line 11.

# 6. PIPE `|`

The pipe is extremely important in Linux.

Syntax:

```bash
command1 | command2
```

The output from `command1` becomes the input for `command2`.

### Example

```bash
tail -n 10 server.log | grep "ERROR"
```

The process is:

```text
server.log
    ↓
tail -n 10
    ↓
last 10 lines
    ↓
grep "ERROR"
    ↓
ERROR lines
```

# 7. Combining GREP and TAIL

## Last 10 Lines → Find ERROR

```bash
tail -n 10 server.log | grep "ERROR"
```

Meaning:

> Take the last 10 lines, then search those lines for `ERROR`.

---

## Last 15 Lines → Find INFO

```bash
tail -n 15 server.log | grep "INFO"
```

---

## Last 10 Lines → Find WARNING

```bash
tail -n 10 server.log | grep "WARNING"
```

---

## Last 10 Lines → Find ERROR or WARNING

```bash
tail -n 10 server.log | grep -E "ERROR|WARNING"
```

---

## Last 20 Lines → Find Docker

```bash
tail -n 20 server.log | grep "Docker"
```

---

# 8. Important Difference

These two commands are different:

### Command 1

```bash
tail -n 5 server.log | grep "ERROR"
```

Meaning:

> Take the last 5 lines of the file, then find ERROR.

### Command 2

```bash
grep "ERROR" server.log | tail -n 5
```

Meaning:

> Find all ERROR lines first, then show the last 5 ERROR lines.

This difference is very important when working with logs.

# 9. Real-Time Log Monitoring

## Monitor only ERROR messages

```bash
tail -f server.log | grep "ERROR"
```

The command continuously watches the log and displays new lines containing `ERROR`.

---

## Monitor ERROR and WARNING

```bash
tail -f server.log | grep -E "ERROR|WARNING"
```

This is a common pattern for monitoring logs.

# 11. Bash Scripting Example

You can use `grep` and `tail` inside Bash scripts.

Create:

```bash
vim log-check.sh
```

Example:

```bash
#!/bin/bash

LOG_FILE="server.log"

echo "===== Latest Errors ====="
grep "ERROR" "$LOG_FILE" | tail -n 5

echo
echo "===== Latest Warnings ====="
grep "WARNING" "$LOG_FILE" | tail -n 5
```

Give execute permission:

```bash
chmod +x log-check.sh
```

Run:

```bash
./log-check.sh
```

# 13. Quick Cheat Sheet

| Command | Purpose |
|---|---|
| `grep "word" file` | Search for text |
| `grep -i "word" file` | Ignore case |
| `grep -n "word" file` | Show line numbers |
| `grep -c "word" file` | Count matching lines |
| `grep -v "word" file` | Show non-matching lines |
| `grep -E "A\|B" file` | Search multiple patterns |
| `tail file` | Last 10 lines |
| `tail -n 5 file` | Last 5 lines |
| `tail -f file` | Follow file in real time |
| `tail -n +10 file` | Start from line 10 |
| `command1 \| command2` | Pipe output |
| `tail file \| grep "ERROR"` | Search tail output |
| `grep "ERROR" file \| tail -n 5` | Latest 5 errors |

# 14. Key Concept

Remember this:

```text
grep = SEARCH
tail = LAST PART
-f   = FOLLOW
|    = CONNECT COMMANDS
```

A very useful DevOps pattern is:

```bash
tail -f application.log | grep -E "ERROR|WARNING"
```

It means:

> **Continuously monitor the application log and show only errors and warnings.**
