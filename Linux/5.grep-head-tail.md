# Linux `grep`, `head`, and `tail` Practice Guide

## 1. Introduction

These three commands are very useful when working with Linux files and server logs:

- `grep` → Search for text or patterns
- `head` → Display the beginning of a file
- `tail` → Display the end of a file

The pipe `|` is used to combine commands.

---

# 2. `head`

`head` displays the first part of a file.

## Basic command

```bash
head server.log
```

By default, it displays the first 10 lines.

## Show the first 5 lines

```bash
head -n 5 server.log
```

## Show the first 20 lines

```bash
head -n 20 server.log
```

Short form:

```bash
head -5 server.log
```

---

# 3. `tail`

`tail` displays the last part of a file.

## Basic command

```bash
tail server.log
```

By default, it displays the last 10 lines.

## Show the last 5 lines

```bash
tail -n 5 server.log
```

## Show the last 20 lines

```bash
tail -n 20 server.log
```

Short form:

```bash
tail -5 server.log
```

## Follow a file in real time

```bash
tail -f server.log
```

This is very useful for monitoring log files.

Stop it with:

```text
Ctrl+C
```

---

# 4. `grep`

`grep` searches for text or patterns inside files.

## Basic command

```bash
grep "ERROR" server.log
```

This displays every line containing `ERROR`.

## Ignore case

```bash
grep -i "error" server.log
```

This matches:

```text
ERROR
Error
error
ERROR
```

## Show line numbers

```bash
grep -n "ERROR" server.log
```

## Count matching lines

```bash
grep -c "ERROR" server.log
```

## Invert the search

```bash
grep -v "ERROR" server.log
```

This displays lines that do not contain `ERROR`.

## Search multiple patterns

```bash
grep -E "ERROR|WARNING" server.log
```

This searches for either `ERROR` or `WARNING`.

# 8. Combining `grep` and `head`

## Search first, then show the first 5 matches

```bash
grep "ERROR" server.log | head -n 5
```

Meaning:

```text
server.log
   ↓
grep ERROR
   ↓
all ERROR lines
   ↓
head -n 5
   ↓
first 5 ERROR lines
```

---

# 9. Combining `grep` and `tail`

## Search first, then show the latest 5 matches

```bash
grep "ERROR" server.log | tail -n 5
```

Meaning:

```text
server.log
   ↓
grep ERROR
   ↓
all ERROR lines
   ↓
tail -n 5
   ↓
latest 5 ERROR lines
```

# 11. `tail` + `grep`

```bash
tail -n 10 server.log | grep "ERROR"
```

Meaning:

> Take the last 10 lines, then search for `ERROR`.

---

# 12. Important Difference

These commands produce different results.

## Command 1

```bash
tail -n 5 server.log | grep "ERROR"
```

Meaning:

> Take the last 5 lines of the file and find `ERROR`.

## Command 2

```bash
grep "ERROR" server.log | tail -n 5
```

Meaning:

> Find all `ERROR` lines first, then display the latest 5 ERROR lines.

This difference is important when working with logs.

---

# 13. Multiple Patterns

Search for `ERROR` or `WARNING`:

```bash
grep -E "ERROR|WARNING" server.log
```

Search only in the last 10 lines:

```bash
tail -n 10 server.log | grep -E "ERROR|WARNING"
```

Search only in the first 10 lines:

```bash
head -n 10 server.log | grep -E "ERROR|WARNING"
```

---

# 14. Real-Time Log Monitoring

## Monitor only errors

```bash
tail -f server.log | grep "ERROR"
```

This continuously monitors the file and displays matching error messages.

## Monitor errors and warnings

```bash
tail -f server.log | grep -E "ERROR|WARNING"
```

This is a common pattern for server and application log monitoring.

## Latest 5 errors


## Latest 3 warnings

```bash
grep "WARNING" server.log | tail -n 3
```

## Count errors

```bash
grep -c "ERROR" server.log
```

## Count warnings

```bash
grep -c "WARNING" server.log
```

## Latest 20 lines containing Docker

```bash
tail -n 20 server.log | grep "Docker"
```

## Latest 20 lines containing Kubernetes

```bash
tail -n 20 server.log | grep "Kubernetes"
```

## Latest 20 lines containing errors or warnings

```bash
tail -n 20 server.log | grep -E "ERROR|WARNING"
```

# 16. Quick Cheat Sheet

| Command | Purpose |
|---|---|
| `head file` | First 10 lines |
| `head -n 5 file` | First 5 lines |
| `tail file` | Last 10 lines |
| `tail -n 5 file` | Last 5 lines |
| `tail -f file` | Follow file in real time |
| `grep "word" file` | Search for text |
| `grep -i "word" file` | Case-insensitive search |
| `grep -n "word" file` | Show line numbers |
| `grep -c "word" file` | Count matching lines |
| `grep -v "word" file` | Show non-matching lines |
| `grep -E "A\|B" file` | Search multiple patterns |
| `head file \| grep "ERROR"` | Search first part |
| `tail file \| grep "ERROR"` | Search last part |
| `grep "ERROR" file \| head` | First matching lines |
| `grep "ERROR" file \| tail` | Latest matching lines |

# 18. Key Concepts to Remember

```text
grep = SEARCH
head = BEGINNING
tail = END
-f   = FOLLOW
|    = PIPE / CONNECT COMMANDS
```

A very useful DevOps log-monitoring command is:

```bash
tail -f server.log | grep -E "ERROR|WARNING"
```

It means:

> Continuously monitor the server log and display only ERROR and WARNING messages.
